# Design Document: Renew

**Author:** Scott Idler
**Date:** 2026-05-01
**Status:** In Review
**Review Passes Completed:** 5/5

## Summary

`renew` is a Rust library that gives a CLI binary the ability to check for newer versions of itself on GitHub releases and replace its own on-disk file with the latest build. It is consumed by a fleet of internal tools (`ccu`, `cr`, `claude-permit`) and is designed to be a one-line drop-in for passive update notifications plus a turnkey `<bin> update` subcommand for explicit upgrades.

## Problem Statement

### Background

Three internal CLIs — `claude-cost-usage` (binary `ccu`), `claude-report` (binary `cr`), and `claude-permit` — each ship versioned binaries via GitHub releases under `tatari-tv/`. All three follow the same release pipeline: a tag `vX.Y.Z` push triggers a workflow that builds four platform tarballs (`linux-amd64`, `linux-arm64`, `macos-x86_64`, `macos-arm64`), each containing a single binary plus a SHA256 sidecar.

Today there is no in-binary mechanism to detect when a newer release exists, and no mechanism for the binary to update itself. Users either notice via Slack, run `cargo install --git ...` manually, or just keep running stale versions. The first symptoms — a missing feature, an old bug — surface long after a fix has shipped.

### Problem

Every Consumer needs:

1. A way to **passively notice** that a newer release exists, surfaced to the user only when interactive (must not corrupt non-TTY output paths like `ccu` calls from `~/.claude/statusline.sh`).
2. A way for the user to **explicitly upgrade** via a CLI subcommand (`<bin> update install`), with the running binary capable of replacing itself on disk.
3. A way to **revert** if a new version misbehaves, restoring the immediately previous binary.

Each Consumer reimplementing this is duplication and risk. The atomic-rename trick for replacing a running binary, SHA verification, GitHub API parsing, rate-limit handling, cache TTL — none of it is hard, but each of them is easy to get subtly wrong. A shared library is the right move.

### Goals

- **One-line passive notification.** A Consumer drops `renew::renew!().notify_if_outdated();` into `main()` and gets stderr notification on interactive invocations only.
- **Turnkey explicit upgrade subcommand.** A Consumer plugs `renew::UpdateCmd` into its `clap` enum and gets `<bin> update {install [version] [--force], check, revert}` for free.
- **Composable lower-level API** for Consumers that want JSON/programmatic output (e.g. ccu's statusline-friendly combined command).
- **Safe by default.** Strict confirmation prompt on destructive operations; SHA verification mandatory; non-TTY stdin requires `--yes`; backup is captured before every install; revert is exactly one operation away.
- **Zero impact on non-TTY callers.** Statusline-style invocations (stderr piped to `/dev/null`, frequent calls) must not slow down, must not print, and must not exhaust GitHub rate limits.
- **Works with both `env_logger` and `tracing` Consumers** (heterogeneous fleet — ccu uses env_logger, pd-style consumers use tracing).
- **Auth-ready.** Anonymous works for today's public repos; private-repo support comes "for free" via env-var-driven token (`GH_TOKEN` / `GITHUB_TOKEN`).

### Non-Goals

- **Windows.** None of today's Consumers ship Windows binaries; release pipelines don't produce them.
- **Package-manager integration** (apt/dnf/homebrew). Consumers are installed via `cargo install` to user-owned paths.
- **Privilege escalation.** If `current_exe()` lives in a system-owned path (e.g. `/usr/local/bin`), renew will fail with a permission error — it will not try `sudo`.
- **N-deep version stack.** Exactly one previous-version backup. For arbitrary rollback, use `install <specific-version>`.
- **Notification de-dup state.** Every interactive invocation prints if outdated. Simpler than tracking what we've already nagged the user about, and a persistent reminder is desirable.
- **Async API.** All current Consumers are sync; a sync API keeps the dependency graph small. Async-needing future consumers can wrap in `tokio::task::spawn_blocking`.
- **Custom HTTP backends.** Pinned to `ureq` + rustls. Not configurable.
- **Custom asset naming schemes.** The library hardcodes the `<bin>-v<X.Y.Z>-<suffix>.tar.gz` contract. Consumers whose release pipelines diverge from it cannot use renew until aligned.

## Proposed Solution

### Overview

A library crate `renew` exposing:

- A core **`Renew`** struct holding Consumer identity (repo slug, binary name, current version) and optional configuration (cache TTL, install path override, auth token).
- **Core methods** `check_latest`, `install_latest`, `install_version`, `revert` that return `Result<T, Error>` with a typed `thiserror` enum.
- An **infallible helper** `notify_if_outdated` that wraps `check_latest`, gates printing on `stderr.is_terminal()`, and swallows network errors. Designed for one-line drop-in.
- A **reusable `clap::Args` subcommand** `UpdateCmd` that wires up `install` / `check` / `revert` with strict confirmation prompts and machine-friendly exit codes.
- A **`renew!()` macro** for the no-arg ergonomic constructor that pulls repo/bin/version from cargo env vars.

The library is sync, depends on `ureq` + `rustls` for HTTP, `self_replace` for atomic binary swap, `thiserror` for typed errors, `log` for logging, `serde` + `serde_yaml` for cache/backup metadata, `semver` for version parsing, `flate2` + `tar` for extraction, `sha2` for verification.

### Data Model

#### `RepoSlug` (private type)

```rust
struct RepoSlug {
    owner: String,
    repo: String,
}

impl RepoSlug {
    fn parse(input: &str) -> Result<Self>;
    //  Accepted input forms:
    //    "owner/repo"
    //    "https://github.com/owner/repo"           (with optional .git, trailing /)
    //    "http://github.com/owner/repo"            (downgraded to https in normalization)
    //    "git@github.com:owner/repo.git"           (SSH form — common in `repository = "..."`)
    //    "ssh://git@github.com/owner/repo.git"     (alternate SSH form)
    fn as_path(&self) -> String;                    // "owner/repo"
}
```

Normalization rules: strip leading scheme/host; for SSH form, treat the colon-or-slash after the host as the owner separator; strip trailing `/`; strip trailing `.git`; reject if missing exactly one `/` between owner and repo; reject empty input with the documented "did you set `repository = "..."`?" message.

#### `Renew` (the public struct)

```rust
pub struct Renew {
    repo: RepoSlug,                  // "owner/repo", normalized from URL or slug
    bin: String,                     // "ccu" — the binary name (= asset prefix)
    current: semver::Version,        // env!("CARGO_PKG_VERSION") parsed
    cache_ttl: Duration,             // default: 24h
    cache_dir: PathBuf,              // default: dirs::cache_dir().join(&bin) — shared across installs (cache content is "what's the latest on GitHub")
    data_dir: PathBuf,               // default: dirs::data_local_dir().join(&bin) — root; per-install backup lives in a hashed subdir (see Filesystem Layout)
    install_path: Option<PathBuf>,   // None = use current_exe() at install time
    token: TokenSource,              // Default = env-auto, Explicit(Some)/Explicit(None) overrides
    network_timeout: Duration,       // default: 5s for API, 60s for downloads
}

enum TokenSource {
    EnvAuto,                         // read GH_TOKEN, then GITHUB_TOKEN
    Explicit(Option<String>),        // builder override
}
```

Constructor: `Renew::new(repo: impl AsRef<str>, bin: impl AsRef<str>, current: impl AsRef<str>) -> Result<Self>`. Validates repo (URL or slug), parses version. Builder methods (`with_cache_ttl`, `with_token`, `with_install_path`) return `Self` for chaining.

#### `Update` (returned by `check_latest`)

```rust
pub struct Update {
    pub current: semver::Version,
    pub latest: semver::Version,
    pub tag: String,                          // "v0.5.0"
    pub release_url: String,
    pub published_at: chrono::DateTime<Utc>,
}
```

`check_latest` returns `Result<Option<Update>>` — `None` = already current, `Some(u)` = `latest > current`.

#### `InstalledVersion` (returned by `install_*` and `revert`)

```rust
pub struct InstalledVersion {
    pub from: semver::Version,
    pub to: semver::Version,
    pub path: PathBuf,                        // where the new binary now lives
}
```

#### Cache file: `<cache_dir>/check.yml`

```yaml
latest-version: 0.5.0
checked-at: 2026-05-01T08:00:00Z
```

#### Backup metadata: `<data_dir>/<install-hash>/backup/meta.yml`

```yaml
version: 0.4.3
saved-at: 2026-05-01T08:30:00Z
original-path: /home/scott/.cargo/bin/ccu
```

(Plus `<data_dir>/<install-hash>/backup/binary` — the actual binary, mode 755.)

`<install-hash>` is the first 12 hex chars of `sha256(canonical(install_path))`. Rationale: a single user environment can legitimately host multiple copies of the same binary (e.g. stable in `~/.cargo/bin/ccu` and an experimental build in `/tmp/ccu`). Keying the backup by binary name alone causes cross-installation corruption — installing over the experimental copy would overwrite the stable copy's backup, and a later `revert` on the stable copy would restore the experimental binary into the stable path. Hashing the canonical install path gives each install its own backup slot. Cache stays shared (it's GitHub-state, install-independent).

#### Error enum

```rust
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("invalid repo identifier: {0}")] InvalidRepo(String),
    #[error("malformed release tag {tag}: {source}")] InvalidTag { tag: String, #[source] source: semver::Error },
    #[error("no release found for {repo}")] NoRelease { repo: String },
    #[error("rate limited by GitHub; retry after {retry_after:?}")] RateLimited { retry_after: Option<Duration> },
    #[error("no release asset for platform {os}-{arch}")] AssetMissing { os: String, arch: String },
    #[error("checksum mismatch: expected {expected}, got {actual}")] ChecksumMismatch { expected: String, actual: String },
    #[error("tarball must contain exactly one file; found {count}")] TarballShape { count: usize },
    #[error("cannot write to install path {path}: {source}")] InstallPath { path: PathBuf, #[source] source: io::Error },
    #[error("no backup available to revert to")] NoBackup,
    #[error("network error: {0}")] Network(#[from] ureq::Error),
    #[error("io error: {0}")] Io(#[from] io::Error),
    #[error("yaml error: {0}")] Yaml(#[from] serde_yaml::Error),
    #[error("json error: {0}")] Json(#[from] serde_json::Error),
    #[error("a confirmation prompt was required but stdin is not a TTY; use --yes to bypass")]
    PromptRequiredButStdinNotTty,
}

pub type Result<T> = std::result::Result<T, Error>;
```

### API Design

#### Layer (a): core methods on `Renew`

```rust
impl Renew {
    pub fn new(repo: impl AsRef<str>, bin: impl AsRef<str>, current: impl AsRef<str>) -> Result<Self>;
    pub fn with_cache_ttl(self, ttl: Duration) -> Self;
    pub fn with_network_timeout(self, timeout: Duration) -> Self;   // default 5s API, 60s download
    pub fn with_token(self, token: Option<String>) -> Self;
    pub fn with_install_path(self, path: PathBuf) -> Self;

    /// Returns Some(Update) if a newer release exists, None if up to date.
    /// Honors the cache; only hits GitHub if cache is stale or absent.
    pub fn check_latest(&self) -> Result<Option<Update>>;

    /// Force a network call, bypassing the cache. Still updates the cache afterward.
    pub fn check_latest_refresh(&self) -> Result<Option<Update>>;

    /// Verify that `install_path` is writable without doing a full install. Cheap.
    /// Used internally as the pre-flight step in `install_*`; exposed for callers
    /// that want to fail fast before downloading.
    pub fn preflight(&self) -> Result<()>;

    /// Download, verify, extract, backup current, atomic-replace. Returns the new state.
    pub fn install_latest(&self) -> Result<InstalledVersion>;

    /// Same pipeline targeting a specific version.
    pub fn install_version(&self, version: &semver::Version) -> Result<InstalledVersion>;

    /// Restore the backup; consumes (deletes) it. Errors NoBackup if none exists.
    pub fn revert(&self) -> Result<InstalledVersion>;

    /// Whether a backup exists right now.
    pub fn has_backup(&self) -> bool;
}
```

#### Layer (b): infallible notification helper

```rust
impl Renew {
    /// Refresh cache if stale; print "new version vX.Y.Z available" to stderr
    /// only when stderr is a TTY and `latest > current`. Swallows all errors
    /// (logged at debug). Safe to drop into any main(), including those
    /// invoked from non-TTY contexts like statusline scripts.
    pub fn notify_if_outdated(&self);
}
```

#### Layer (c): `clap::Args` subcommand

```rust
#[derive(clap::Args)]
pub struct UpdateCmd {
    #[command(subcommand)]
    cmd: Option<UpdateSub>,
}

#[derive(clap::Subcommand)]
enum UpdateSub {
    /// Check whether an update is available (exit 0 = current, 1 = update available, 2 = error).
    Check {
        #[arg(long)] refresh: bool,                      // bypass cache
    },
    /// Install a specific version (defaults to latest).
    Install {
        version: Option<String>,
        #[arg(long)] force: bool,
        #[arg(long)] yes: bool,
        #[arg(long)] refresh: bool,                      // bypass cache when resolving "latest"
        #[arg(long)] install_path: Option<PathBuf>,
    },
    /// Revert to the previously installed version.
    Revert {
        #[arg(long)] yes: bool,
        #[arg(long)] install_path: Option<PathBuf>,
    },
}

impl UpdateCmd {
    /// Run the subcommand and return a process exit code.
    /// Infallible from the Consumer's perspective: errors are rendered to stderr
    /// and reported as exit code 2. This avoids colliding with eyre's default
    /// "exit 1 on Err" — exit 1 is reserved for `check`'s "update available" signal.
    /// Consumer pattern:
    ///     Cmd::Update(cmd) => process::exit(cmd.run(&renew)),
    pub fn run(&self, renew: &Renew) -> i32;
}
```

The exit code contract is:

| Code | Meaning | Subcommand |
|------|---------|------------|
| 0 | Success / already current | all |
| 1 | Update available | `check` only |
| 2 | Error (network, permission, checksum, etc.) — rendered to stderr | all |

`run()` is intentionally infallible from the Consumer's perspective so that exit code 1 has unambiguous meaning. The Consumer just `process::exit(cmd.run(&renew))`.

#### Macro

```rust
#[macro_export]
macro_rules! renew {
    () => {
        $crate::Renew::new(
            env!("CARGO_PKG_REPOSITORY"),
            env!("CARGO_PKG_NAME"),
            env!("CARGO_PKG_VERSION"),
        )
    };
    (bin = $bin:expr) => {
        $crate::Renew::new(env!("CARGO_PKG_REPOSITORY"), $bin, env!("CARGO_PKG_VERSION"))
    };
    (repo = $repo:expr) => {
        $crate::Renew::new($repo, env!("CARGO_PKG_NAME"), env!("CARGO_PKG_VERSION"))
    };
    (repo = $repo:expr, bin = $bin:expr) => {
        $crate::Renew::new($repo, $bin, env!("CARGO_PKG_VERSION"))
    };
    (bin = $bin:expr, repo = $repo:expr) => {
        $crate::Renew::new($repo, $bin, env!("CARGO_PKG_VERSION"))
    };
}
```

The macro returns `Result<Renew>`. Consumer uses `?` or `unwrap_or_else` as appropriate.

**Empty `CARGO_PKG_REPOSITORY` handling:** cargo always sets the env var (to an empty string if `repository = "..."` is absent in `Cargo.toml`). The no-arg macro form must therefore detect the empty case and produce a clear error message naming the missing field. `Renew::new` does this via the `InvalidRepo("")` variant, with the error message instructing the user to either set `repository` in `Cargo.toml` or use `renew!(repo = "...")` explicitly. We do not need (and do not use) a const-time assertion for this — runtime is fine because the error fires the first time the Consumer is run.

#### Platform detection

A single private helper:

```rust
fn current_platform() -> Result<&'static str> {
    // Reject musl builds explicitly: the release pipeline produces glibc binaries only.
    // Without this guard, a musl-compiled consumer would download `linux-amd64` (a glibc
    // binary), pass SHA verification, replace itself, and then crash on next invocation
    // with a cryptic dynamic-linker error. Detection is compile-time: the consumer is
    // running, so its target_env is known.
    if cfg!(all(target_os = "linux", target_env = "musl")) {
        return Err(Error::AssetMissing {
            os: "linux-musl".to_string(),
            arch: env::consts::ARCH.to_string(),
        });
    }
    Ok(match (env::consts::OS, env::consts::ARCH) {
        ("linux", "x86_64")   => "linux-amd64",
        ("linux", "aarch64")  => "linux-arm64",
        ("macos", "x86_64")   => "macos-x86_64",
        ("macos", "aarch64")  => "macos-arm64",
        (os, arch) => return Err(Error::AssetMissing { os: os.to_string(), arch: arch.to_string() }),
    })
}
```

Asset URL construction:
```
https://github.com/{repo}/releases/download/v{X.Y.Z}/{bin}-v{X.Y.Z}-{platform}.tar.gz
```

#### Consumer integration example

A complete `main.rs` for a Consumer pulling renew in:

```rust
use clap::Parser;
use eyre::Result;

#[derive(Parser)]
struct Cli {
    #[command(subcommand)]
    command: Cmd,
}

#[derive(clap::Subcommand)]
enum Cmd {
    Today { #[arg(long)] total: bool },
    // ... other existing subcommands ...
    Update(renew::UpdateCmd),       // drop-in subcommand
}

fn main() -> Result<()> {
    env_logger::init();
    let renew = renew::renew!()?;   // env-driven: repo from CARGO_PKG_REPOSITORY, etc.
    renew.notify_if_outdated();     // silent on non-TTY stderr; one line on TTY

    let cli = Cli::parse();
    match cli.command {
        Cmd::Update(cmd) => std::process::exit(cmd.run(&renew)),
        Cmd::Today { total } => { /* existing logic */ }
        // ...
    }
    Ok(())
}
```

For Consumers whose binary name differs from their package name (e.g. `cr` whose package is `claude-report`):

```rust
let renew = renew::renew!(bin = "cr")?;
```

For Consumers whose Cargo.toml `repository` is unset and they don't want to set it:

```rust
let renew = renew::renew!(repo = "tatari-tv/claude-report", bin = "cr")?;
```

#### User-visible output examples

What end-users see when they run each command. These are the concrete strings the implementation must produce:

**`notify_if_outdated` — interactive (TTY) and outdated:**
```
ccu: new version 0.5.0 available (currently 0.4.3)  → ccu update install
```
**`notify_if_outdated` — non-TTY or up-to-date:** silent.

**`<bin> update check` — up to date (exit 0):**
```
ccu 0.4.3 (latest)
```
**`<bin> update check` — update available (exit 1):**
```
ccu 0.4.3 → 0.5.0 available (released 2026-05-01)
```
**`<bin> update check` — error (exit 2):**
```
error: rate limited by GitHub; retry after 47s
```

**`<bin> update install` — interactive prompt:**
```
ccu: install 0.5.0 over 0.4.3 (replacing /home/scott/.cargo/bin/ccu)? [Y/n] _
```
**`<bin> update install --yes` — successful:**
```
ccu: installed 0.5.0 (was 0.4.3)
```
**`<bin> update install` — already current:**
```
ccu: already on 0.4.3 (latest). Use --force to reinstall.
```

**`<bin> update revert` — interactive prompt:**
```
ccu: revert 0.5.0 → 0.4.3 (restoring /home/scott/.cargo/bin/ccu)? [Y/n] _
```
**`<bin> update revert --yes` — successful:**
```
ccu: reverted to 0.4.3 (was 0.5.0). No further previous version available.
```
**`<bin> update revert` — no backup:**
```
error: no backup available to revert to
```

These strings are written to stderr (`notify_if_outdated`, prompts, errors) or stdout (success messages) deliberately: anything stdout-bound stays parseable for piping; anything diagnostic or interactive stays on stderr.

### Implementation Plan

#### Phase 1: Scaffold cleanup and baseline commit
**Model:** sonnet

- Strip the demo bits from the scaffold: delete `src/cli.rs`, `src/config.rs`, `src/main.rs`, `src/config/`, `renew.yml`. Keep `build.rs` (for `GIT_DESCRIBE`), `Cargo.toml`, `clippy.toml`, `.otto.yml`, `.pre-commit-config.yaml`.
- Update `Cargo.toml`: real author, real description, drop `colored` and `dirs` (will re-add as deps used by the lib), set `[lib]` with `path = "src/lib.rs"`. Set `repository = "https://github.com/tatari-tv/renew"`.
- Add lib-level deny attributes to `src/lib.rs`: `#![deny(clippy::unwrap_used)]`, `#![deny(dead_code)]`, `#![deny(unused_variables)]`.
- Add deps via `cargo add`: `ureq` (rustls feature), `self_replace`, `thiserror`, `log`, `semver`, `serde` (derive), `serde_yaml`, `serde_json`, `flate2`, `tar`, `sha2`, `chrono` (serde feature), `dirs`, `clap` (derive feature). File locking uses `std::fs::File::try_lock` (Rust 1.89+); no crate needed.
- Add `rust-version = "1.89"` to `Cargo.toml` `[package]` to make the std-locking floor explicit. (ccu's pinned 1.94.1 is well above this.)
- Commit baseline: untracked scaffold files become tracked. Run `otto ci` to confirm green.

#### Phase 2: Core types and builder
**Model:** sonnet

- `src/error.rs`: the `Error` enum and `Result<T>` alias.
- `src/repo.rs`: `RepoSlug::parse` covering URL forms, bare-slug forms, `.git` suffixes, trailing slashes, the "empty CARGO_PKG_REPOSITORY" path with the actionable error message.
- `src/version.rs`: tag-to-semver parsing (strip leading `v`), the `Update` struct.
- `src/platform.rs`: `current_platform()` returning the asset suffix.
- `src/renew.rs`: the `Renew` struct, `TokenSource` enum, `Renew::new`, builder methods. No I/O yet.
- `src/lib.rs`: re-exports, the `renew!` macro, crate-level deny attrs.
- Per-module unit tests in `src/<mod>/tests.rs`: URL/slug normalization (`https://github.com/tatari-tv/ccu`, `tatari-tv/ccu`, `tatari-tv/ccu.git`, `https://github.com/tatari-tv/ccu/` all normalize identically), tag parsing rejects malformed input (no `v` prefix is fine, `v1.2.x` is rejected, etc.), builder defaults, platform table exhaustive (4 supported tuples, every other tuple → `AssetMissing`).

#### Phase 3: GitHub client + cache + `check_latest`
**Model:** opus

- `src/github.rs`: small client around `ureq`. Methods:
  - `latest_release(repo, token: Option<&str>) -> Result<ReleaseInfo>` — calls `GET /repos/{owner}/{repo}/releases/latest`. Note: this endpoint **excludes drafts and prereleases** — the latest published, non-prerelease release. That matches our intent (Consumers don't want auto-update to a beta).
  - `ReleaseInfo` includes `tag_name`, `published_at`, `html_url`, **and the full asset list** (name + browser_download_url). The install pipeline picks the asset whose name matches `{bin}-{tag}-{platform}.tar.gz` from this list — *not* by blind URL construction. If no matching asset is in the list, return `AssetMissing` immediately rather than discovering it via 404 mid-download.
  - `download_asset(url, token, dest_path) -> Result<()>` — streaming download with **belt-and-suspenders auth scrubbing**:
    - The *initial* request to `github.com` carries `Authorization: Bearer <token>`.
    - The redirect to the S3 presigned URL must NOT carry the token. Defense in two layers:
      1. ureq is configured with `redirect_auth_headers(SameHost)` so auth is auto-stripped on cross-host redirects.
      2. As an explicit guard, the implementation manually inspects the response: if status is 3xx and the `Location` host differs from `github.com`, it issues the next request with a fresh request builder that has no auth header. This makes the no-leak invariant visible in the code, not silently dependent on a configuration option.
    - Handles 401/403/404/429 → typed errors; 5xx → one retry.
- `src/cache.rs`: load/save `<cache_dir>/check.yml`, with TTL evaluation. `is_fresh(ttl)`, `latest_version()`, `record(latest, now)`. Atomic write (temp file + rename) to avoid torn writes.
- Wire `Renew::check_latest`: read cache → if fresh, return cached compared to `current` → if stale, **acquire `<cache_dir>/refresh.lock` non-blocking** → fetch (one process at a time), write cache, release lock, compare, return.
  - The lock prevents a thundering-herd refresh: if `ccu` is invoked from a tmux statusline three times per second from four panes, the cache will go stale once per 24h. Without the lock, all 12 invocations in that second would race to call GitHub. With non-blocking `File::try_lock`, the first invocation does the network call; the rest find the lock held and **fall through to the existing (still-stale) cache** — which is fine, the next invocation a fraction of a second later will see the freshly-written cache. We do *not* block waiting for the lock (would tank statusline latency).
  - Implementation: `std::fs::File::try_lock` on a sentinel file. Stabilized in Rust 1.89 (Aug 2025); ccu pins Rust 1.94.1, so the floor is fine. Std uses `flock(LOCK_EX | LOCK_NB)` on Unix (macOS and Linux both) and `LockFileEx` with `LOCKFILE_FAIL_IMMEDIATELY` on Windows — but Windows is non-goal so only the Unix path matters. Per-fd advisory lock; released automatically on `File` drop. **No external locking crate needed** — `fs2`/`fs4` would just wrap this same syscall.
  - macOS portability: `flock(2)` works correctly for local files on macOS. `~/Library/Caches/<bin>/` is always on a local filesystem, so the lock is effective. Linux's `~/.cache/<bin>/` is local in standard distributions; the rare NFS-home case would have flock no-op, in which case the thundering herd happens but cache writes are atomic-rename so nothing corrupts — only outcome is a few extra anonymous GitHub calls during a stale-cache moment. Acceptable.
- Wire `Renew::check_latest_refresh`: skip the cache read; still take the lock (non-blocking) and still write the cache after. If the lock is held, fall through to the cache (the explicit `--refresh` flag effectively becomes "best-effort refresh").
- Stale-cache fallback: if a network call fails while cache is stale, fall back to the stale cache (logged `warn!`). Only if both fail does `check_latest` return `Err(Network(...))`.
- Tests: in-memory fakes for the GitHub client and cache. Cover: fresh cache hit, stale cache fetch, network error with stale cache fallback, rate-limit error mapping, malformed tag mapping, **redirect to non-github host strips auth**, **concurrent refresh: only one network call escapes the lock**.

#### Phase 4: Install pipeline + revert
**Model:** opus

- `src/install.rs`: the linear pipeline. Each step lives in a private function so it's individually testable.
  - `resolve_install_path(&self) -> Result<PathBuf>` — `self.install_path.clone()` else `env::current_exe()?` canonicalized.
  - `preflight(install_path) -> Result<()>` — verify writability of the install path itself, not its parent. Strategy:
    - If `install_path` exists: open with `OpenOptions::new().write(true).truncate(false).open(&install_path)` — succeeds iff the file itself is writable. Drop the handle immediately. This handles the common UNIX deployment where a user owns a binary in a directory they don't own (e.g. `chown user /usr/local/bin/ccu` with parent `/usr/local/bin/` root-owned).
    - If `install_path` does not exist (first install): fall back to creating-and-deleting a sentinel `<install_path>.preflight` in the parent directory. Without an existing file, parent-dir writability is the only test available.
    - Maps any error to `Error::InstallPath { path, source }` with the original `io::Error`.
  - `download_asset` (delegates to `github.rs`).
  - `verify_sha256(tarball, sidecar) -> Result<()>` — parse sidecar (take first 64 hex chars; tolerate `<hex>  <name>` and `<hex> *<name>` variants), hash tarball, compare.
  - `extract_single(tarball, dest_dir) -> Result<PathBuf>` — open tar.gz, walk entries, **filter to regular files only** (a tarball with a `./` directory entry plus one binary still counts as one file). Fail with `TarballShape { count }` if the regular-file count is not exactly 1. Extract to `dest_dir/<bin>`.
  - `chmod_executable(path) -> Result<()>` — Unix only; `cfg(windows)` no-op (Windows never reaches this code path because `AssetMissing` triggers earlier).
  - `backup_dir(install_path) -> PathBuf` — `<data_dir>/<sha256(canonical(install_path))[:12]>/backup/`. Computed once per install operation.
  - `capture_backup(install_path, current_version) -> Result<()>` — atomic-write both files into `backup_dir(install_path)`: `fs::copy` to `binary.new` then `fs::rename` to `binary`; serialize meta to `meta.yml.new` then rename to `meta.yml`. The order matters: write binary first, meta last — so a torn write leaves the old (consistent) backup intact. The original installed binary is **never moved**, only copied; the live binary stays in place until the replace step.
  - `replace_in_place(staged_binary, install_path) -> Result<()>` — if `install_path == current_exe()` (canonicalized, both sides), use `self_replace::self_replace(staged_binary)`; else use `fs::rename(staged_binary, install_path)`. The staged binary is at `<install_path>.new` (sibling of target) so the rename is always same-filesystem.
    - **Note on non-`current_exe()` install paths:** when the user passes `--install-path /elsewhere/<bin>` and *another* process is currently executing that binary, Linux/macOS allow the rename — the running process keeps its in-memory image (the inode is still valid) and the file at the path is now the new binary. This is the same outcome as `self_replace` provides for `current_exe()`. We do not detect or warn about this case; it matches the documented contract that "renew replaces the binary at `install_path`."
- Pipeline ordering inside `install_*`:
  1. `resolve_install_path` → 2. `preflight` → 3. fetch release info (or use cached) → 4. resolve target version, gate on `force` if `target == current` → 5. confirm prompt (in `UpdateCmd`, not in `Renew`) → 6. download tarball + sidecar to `<cache_dir>/download/` → 7. verify SHA256 → 8. extract to `<install_path>.new` → 9. `chmod_executable` → 10. `capture_backup` → 11. `replace_in_place` → 12. clean up `<cache_dir>/download/` → return `InstalledVersion`.
  - On any error before step 11, `install_path` is untouched. Backup directory is left intact whether or not it was just written (a redundant backup of an unchanged binary is harmless and the next install will overwrite it).
- Wire `Renew::revert`: compute `backup_dir(install_path)`, load its `meta.yml`, verify its `binary` exists, copy to `<install_path>.revert.new`, atomic-replace, delete the per-install backup directory. If no backup at this install path's slot, `Err(NoBackup)` — the user might have a backup at a *different* install path's slot, which is correct: revert is per-install, not global.
- Tests: integration tests using a local fixture tarball (no network). Cover: malformed sidecar (single space, `*` prefix, missing trailing newline), tarball-shape failures (zero files, two files, directories), preflight catching unwritable parent, backup created and consumed by revert, revert without backup, install with `--install-path` to a tmp file.

## Alternatives Considered

### Alternative 1: Use the `self_update` crate directly (no wrapper)

`self_update` is a popular crate that does end-to-end version-check + download + replace from GitHub releases.

- **Pros:** Zero code to write. Battle-tested. Handles platform detection.
- **Cons:** Opinionated configuration model that doesn't fit our asset-naming convention without significant glue. Pulls in `reqwest` + `tokio` (we don't want async). API doesn't expose the data we need for the JSON-output path (Consumer's "is there a newer version?" boolean for statusline). No support for our backup-and-revert flow. No support for `is_terminal`-gated passive notification.
- **Why not chosen:** We'd be writing a wrapper anyway; we may as well write directly against `ureq` + `self_replace` and own the surface.

### Alternative 2: Async API with `reqwest`

- **Pros:** Future-proof if a Consumer ever needs non-blocking checks.
- **Cons:** All current Consumers are sync; forcing them to add `tokio` for "check version on startup" is heavy. Async-needing consumers (none today) can wrap our sync API in `spawn_blocking` cheaply.
- **Why not chosen:** No present need; the cost is paid by every Consumer, today.

### Alternative 3: `tracing` instead of `log`

- **Pros:** Richer observability for tracing-using consumers like `pd`.
- **Cons:** Pulls `tracing` into env_logger consumers' dep graphs; the reverse bridge (`tracing` → `log` via the `log-always` feature) is lossy. Goes against the rust.md default.
- **Why not chosen:** `log` is the lowest-common-denominator facade. Tracing consumers add one bridge line via `tracing-log::LogTracer::init()` and get full fidelity.

### Alternative 4: De-duplicated notifications via `notified_for` cache state

Track in cache "the latest version we already nagged about" so each new version yields exactly one notice per machine.

- **Pros:** Quietest possible UX.
- **Cons:** More state to manage; race conditions if multiple invocations refresh in parallel; user might miss the one notice and never see another. Statusline-style callers without TTY-gating would burn the budget.
- **Why not chosen:** With `is_terminal`-gating in place, "print every interactive invocation" is acceptable noise (only interactive sessions see it) and is dead simple. Replaced by Option X.

### Alternative 5: Explicit `with_token_from_env()` rather than auto-read by default

- **Pros:** No implicit env reads.
- **Cons:** Inconsistent with `gh`, `cargo`, GitHub Actions; users with `GITHUB_TOKEN` set generally want GitHub-touching tools to use it; CI-injected tokens go un-used.
- **Why not chosen:** Auto-read is the convention. Failure modes are graceful (anonymous fallback, typed error on bad token). `.with_token(None)` provides an explicit-anonymous escape hatch for tests.

### Alternative 6: List-of-N backup stack

- **Pros:** Multi-step rollback.
- **Cons:** Disk usage grows (binaries are multi-MB); semantic complexity (which is "previous"? top of stack? second?); unclear UX for "revert" subcommand.
- **Why not chosen:** N=1 backup is sufficient for the "I just installed v2.0, it's broken, get me back to v1.0" workflow. For older versions, `install <version>` is the explicit answer.

## Technical Considerations

### Dependencies

Direct (declared in `Cargo.toml`):

| Crate | Purpose |
|-------|---------|
| `ureq` (rustls) | Sync HTTP client |
| `self_replace` | Atomic running-binary swap |
| `thiserror` | Library-style typed errors |
| `log` | Logging facade |
| `semver` | Version comparison |
| `serde` (derive) | Cache + backup serialization |
| `serde_yaml` | Cache + backup file format |
| `serde_json` | GitHub API response parsing |
| `flate2` | gzip decompression |
| `tar` | Tar extraction |
| `sha2` | SHA256 verification |
| `chrono` (serde) | Cache timestamps |
| `dirs` | Platform-native cache/data paths |
| `clap` (derive) | `UpdateCmd` |

No `tokio`, no `reqwest`, no `anyhow`. No `eyre` (libraries use `thiserror`).

### Performance

Cold-path operations (when invoked):
- `notify_if_outdated` with fresh cache: zero network, one file read (~80 bytes). Sub-millisecond.
- `notify_if_outdated` with stale cache: one HTTP call to api.github.com (~1KB response). Typically <500ms; capped at the network timeout (5s).
- `install_latest`: one HTTP call (~1KB) + one HTTP call (~3MB tarball) + one HTTP call (~100B sidecar). SHA256 of a 3MB file is sub-millisecond. Total typically <5s on a fast connection.

The library is leaf code in a CLI startup path; it must not block startup meaningfully. `notify_if_outdated`'s cache-fresh path is the common case and is essentially free.

### Security

- **SHA256 verification is mandatory.** No flag to skip it. The sidecar is downloaded over the same TLS connection as the tarball, so an attacker who could substitute one could substitute the other; verification still catches accidental corruption and provides defense-in-depth against future MITM mitigations.
- **HTTPS only.** ureq with rustls; no insecure fallback.
- **No `unsafe` code in renew itself.** Dependencies (sha2, flate2) may use `unsafe`; we trust them.
- **Tokens never logged, never in error messages.** The `log` calls scrubthe token; `thiserror` variants don't reference it.
- **Tokens never in CLI args.** The `UpdateCmd` does not expose `--token`. Env or builder only.
- **Atomic-rename install.** No window where the binary is half-written or missing. If the new file fails to write, the old file is untouched.
- **Permission-denied paths fail loudly.** No `sudo`, no privilege escalation.

### Testing Strategy

- **Unit tests** for pure logic: URL/slug parsing, version comparison, platform detection table, asset-URL construction, SHA256 hex parsing, cache TTL evaluation.
- **Integration tests** with fakes:
  - Fake `GitHub` trait implementation (returns canned `ReleaseInfo`, simulates rate limit, simulates 5xx).
  - Local fixture tarballs in `tests/fixtures/` for the install pipeline (no network required for this layer).
  - Tempdir for cache_dir / data_dir / install_path. Tests verify post-state on disk.
- **Smoke test against a real release** in a separate `tests/network.rs` gated by `#[ignore]` so it runs only when the developer asks. Hits a real public release of `ccu`.
- Per `rust.md`: test files live in submodules (`src/foo/tests.rs`), not inline `#[cfg(test)] mod tests` blocks.

### Rollout Plan

1. Land renew v0.1.0 (this design's implementation) green on `main`.
2. Wire into `ccu` first as the canary. Verify behavior end-to-end including statusline silence, interactive notifications, install/revert flow.
3. Cut `ccu` v0.5.0 (minor bump because it's a user-visible feature add).
4. After ~one week of `ccu` running with renew in the field, repeat for `cr` and `claude-permit`.
5. Renew's first breaking change (if any) goes to v0.2.0 and Consumers update tags individually.

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Consumer's release pipeline drifts from contract (renamed asset, multi-file tarball, missing platform) | Medium | High (renew silently breaks for that Consumer) | Document the contract in renew's README; renew fails loudly with `AssetMissing` / `TarballShape` rather than silently fall back. Optional: provide a reusable GHA workflow snippet. |
| Atomic rename fails on cross-mount install path (e.g. Consumer installed to a different filesystem from cache_dir) | Low | Medium (install fails) | `replace_in_place` falls back to `fs::copy + remove` if `rename` errors with EXDEV. |
| GitHub anonymous rate limit exceeded on a shared-IP CI runner | Low | Low (notify becomes silent until limit resets; install fails with `RateLimited`) | Auto-read of `GITHUB_TOKEN` (5000 req/hr authenticated) covers GHA explicitly. Stale-cache fallback covers transient interactive cases. |
| Token has insufficient scopes (rare 401 on a public repo) | Low | Low (treated as `RateLimited`-equivalent; cache holds) | Typed error; consumer can choose to retry without token. Document that a missing/scope-restricted token degrades gracefully. |
| Cache file corrupted (interrupted write, manual edit) | Low | Low | Atomic write (temp + rename). On parse error, treat as cache-miss and re-fetch. Logged at `warn!`. |
| Backup file deleted between install and revert (user manually nuked `~/.local/share/<bin>/`) | Low | Low | `revert` returns `NoBackup` cleanly; user falls back to `install <previous-version>`. |
| `current_exe()` not writable (binary in `/usr/local/bin/`, system install) | Medium | Medium (install fails) | `InstallPath` error names the path. User runs with appropriate perms or sets `--install-path`. No silent failure. |
| `tracing` Consumer forgets `LogTracer::init()` and sees no renew logs | Low | Low | README documents the bridge clearly. Logs are diagnostic, not user-facing — missing them doesn't break behavior. |
| Renew's own breaking changes break Consumers | Low | Medium | SemVer tags. Consumers pin specific tags. Breaking changes go to a major bump. |
| Concurrent `<bin> update install` on the same install path | Low | Medium | Pre-flight checks if `<install_path>.new` exists and errors with a hint to delete it. The per-install backup directory (`<data_dir>/<install-hash>/backup/`) further isolates concurrent installs operating on different paths from each other. |
| Concurrent `notify_if_outdated` thundering-herd on stale-cache refresh (e.g. statusline running multiple consumers in parallel) | Medium (statusline use case is real) | Low (rate-limit exhaustion) | Non-blocking `std::fs::File::try_lock` (`flock(LOCK_EX\|LOCK_NB)` on Unix) on `<cache_dir>/refresh.lock` around the network call. First invocation does the fetch; concurrent invocations see the lock held and fall through to the existing stale cache. No process ever blocks waiting. NFS edge case (flock no-ops): herd happens, atomic cache writes ensure no corruption, cost is a handful of anonymous GitHub calls. |
| Backup overwritten across multi-install scenarios (stable in `~/.cargo/bin/ccu`, experimental in `/tmp/ccu`) | Medium (developer workflow) | High (revert restores wrong binary) | Backup directory is keyed by `sha256(canonical(install_path))[:12]`, so each install path has its own slot. A revert on the stable copy can never restore the experimental binary. |
| Auth token leaked to S3 via 302 redirect from GitHub asset URL | Low | High (token leak to third-party host) | Two-layer defense: (1) ureq's `redirect_auth_headers(SameHost)` strips auth on cross-host redirects; (2) `download_asset` explicitly inspects 3xx responses and reissues the request with no auth header if the redirect target is non-`github.com`. |
| Latest release is a draft or prerelease, user expects to see it as "available" | Low | Low | `GET /releases/latest` excludes drafts and prereleases by design — matches our intent. Document so it's not a surprise. v0.2 could add `with_include_prereleases(true)` if needed. |
| Consumer is musl-compiled, `renew` downloads glibc binary, post-install crashes with dynamic-linker error | Medium (Alpine, distroless containers) | High (silent corruption of working install) | `current_platform()` returns `AssetMissing { os: "linux-musl", ... }` at compile time when `cfg(target_env = "musl")`. No download is attempted; user gets a typed error directing them to install via cargo from source. |
| `repository = "..."` uses an SSH URL form (`git@github.com:owner/repo.git`) | Medium (developer workflow) | Low (macro fails at runtime with `InvalidRepo`) | `RepoSlug::parse` accepts SSH forms (`git@host:owner/repo` and `ssh://git@host/owner/repo`) in addition to HTTPS and bare slug. |
